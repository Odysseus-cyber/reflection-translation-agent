# 如何判断反思修订是否有帮助

内置 12 条输入和英美地区对照用于运行检查与案例分析。没有人工审定参考译文，也不输出 BLEU、准确率或预设提升比例。

1. 用选定后端运行 `translate-agent evaluate`，保留模型、生成配置与逐阶段结果。初译和修订必须来自同一次运行，避免用不同输入或不同模型结果混做基线。
2. 将生成的 `manual-review.md` 交给能判断对应语言的人。评审时先不查看逐例审校意见、报告或 `blind-mapping.json`，避免由流程标签影响偏好。
3. 对每个案例分别判断四个维度，记录 A 更好、相当或 B 更好，并引用具体片段。可选填写整体偏好，但不要仅按修改数量或文字长度判断。
4. 完成判断后打开映射文件，将结果转换为“修订更好／相当／初译更好”。若结论无法判断，直接留空并说明原因，不补填分数。
5. 检查修订是否引入新误译、遗漏、过度改写或术语冲突，并将个案结论与运行记录一起保留。

| 维度 | 核对内容 |
| --- | --- |
| 准确性 | 信息是否完整；否定、条件、数量与主体是否保持；有没有添加原文不存在的信息 |
| 流畅性 | 语法、搭配和句子连接是否自然；是否存在直译痕迹 |
| 风格 | 是否符合目标地区及用户指定的文体、语气、敬语和受众 |
| 术语一致性 | 是否使用要求的术语；同一概念是否保持一致；术语是否适合上下文 |

术语检查使用区分大小写的字面子串匹配，只检查原文实际出现的术语。词形变化、大小写变化、合法同义表达可能导致未命中；子串命中也不等于正确使用。占位符比较 `{name}`、`{{name}}`、`${name}`、`%(name)s` 等常见占位符的原样与次数。两项规则均不覆盖整体语义质量。

英美地区案例使用同一中文原文，其他配置保持一致。检查拼写、措辞和产品语气是否适配，并确认没有为了地区化而改变事实。模型可能输出两地都可接受的表达；没有显著差异本身不是失败。

有限案例可以支持具体错误类型的分析，不能直接推出普遍质量优势。汇报时引用实际保存的初译、审校建议和修订片段，并同时展示修订无益或产生问题的案例。
