# 历史失败诊断与本次试验边界

历史数据来自 `artifacts/evaluation/evaluation-2b7834bf-fabc-4c9a-8403-c3bba3023f57` 及 `artifacts/local-smoke`。以下记录只用于发现问题，不计入本次新调用的对照统计。

- `en-zh-business`：初译把 Thursday 写成周五；审校返回维度错位，并重复 “This is the current date”，到 4096 输出 tokens 被截断。
- `zh-en-product`：初译遗漏 14 天期限、自动同步和工作区目的地；首次审校把多个 `dimension` 放入错误分组，结构纠正后四组均为空，遗漏未修复。
- `zh-ja-product`：审校中有“无问题”却列成 issue 的项目；编辑输出“好的，我理解了。请提供您需要翻译的 JSON 数据。”，没有给出日语译文。
- `zh-ja-technical`：初译遗漏双重验证启用条件及无法使用手机时恢复访问的用途；审校宣称无问题但仍列出四个 issue，编辑复述了整个输入 JSON。
- `local-smoke`：原文说免费试用结束后工作区保留 30 天，初译变成免费试用 30 天后到期；修订只把句号改成问号，核心时间关系没有恢复。

试验预先选定上述前四例为诊断组。`zh-en-business` 与 `ja-zh-technical` 为留出组，不参与候选模板的修改；两例只运行冻结候选，不构成同期双臂比较。

本次不重新生成初译。每例的两个审校模板读取完全相同的历史初译。为了独立观察编辑阶段是否服从目标语言和输出格式，两版编辑读取相同的**手工诊断审校报告**，不是各自审校的模型输出。因此试验结果不能直接说明端到端流程改善。

候选保留 `ReviewReport` 合同与原有 Ollama JSON Schema，不改变生产代码。候选审校减少长篇角色叙述、要求最多三条具体问题、明确片段来源；候选编辑使用分隔的原文/初译及简短建议，并重复要求完整目标语言译文。

所有新请求固定使用本机 `gemma3:1b`、temperature 0.2、输出上限 4096 tokens、上下文 16384、单请求超时 120 秒；无格式纠正重试。单次采样不是统计显著性实验。数字、占位符、术语和元话语检查只报告可观察字符串信号，不替代语义人工审校。
